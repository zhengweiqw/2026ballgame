# 平台生成规则需求文档

> 状态：草案  
> 目标版本：V1 微信小游戏  
> 负责人：待定  
> 最近更新：2026-09-05

路线掩码、分叉和移动规则单独成文，避免把《关卡结构与难度曲线》做成总账本。进关时机、倒计时、层数与保底分仍以那份文档为准。

## 1. 背景与目标

标准模式每一关约 50 层。平台必须在开场倒计时前生成完毕，保证：

- 永远有至少一条可完成路线。
- 默认只能跳到相邻列，不会出现跨空列的必死布局。
- 大多数层只有一个正确落点，强度不被双板稀释。
- 每一关有少量短分叉，作为短暂双选。
- 以后若出现穿墙或跨列强化，只需替换移动规则，不必改层数据格式。

## 2. 范围

### 2.1 本期包含

- 三列掩码表示。
- 默认相邻移动规则。
- 进关一次生成本关全部逻辑层。
- 单路主路径。
- 每关 1～3 次短分叉及其收束。
- 分叉出现窗口和间隔。
- 为跨列移动预留规则接口。

### 2.2 本期不包含

- 无限模式路段生成。
- 穿墙、跨列强化的具体数值。
- 按 80/20 随机铺双板。
- 平台 3D 模型和对象池实现细节。
- 果实混出比例。
- 三种手势的最终权重微调。

## 3. 表示法

### GAME-GEN-001 三列掩码

每一层用 `(左, 中, 右)` 三个 0/1 表示。`1` 为可落平台，`0` 为空。

| 示例 | 含义 |
|---|---|
| `(0,1,0)` | 只有中间有板 |
| `(1,0,0)` | 只有左边有板 |
| `(1,1,0)` | 左和中有板 |
| `(1,0,1)` | 左和右有板，中间空 |

列编号：左 = 0，中 = 1，右 = 2。

### GAME-GEN-002 禁止层

任何一层都不得生成：

- `(0,0,0)` 全空。
- `(1,1,1)` 三满。第一版不允许三个选择。

## 4. 移动规则

### GAME-GEN-003 默认相邻

第一版移动规则为 `Adjacent`。角色从当前列出发，只能落到相邻格，含原地：

| 当前列 | 可落列 |
|---|---|
| 左 | 左、中 |
| 中 | 左、中、右 |
| 右 | 中、右 |

因此 `(1,0,0)` 的下一层不得只有 `(0,0,1)`。人在右时，下一层不得只有 `(1,0,0)`。

### GAME-GEN-004 可达选择

某一层对玩家的「选择数」= 当前列按现行移动规则能落到的、且该层实际有板的列数。

单路层必须恰好 1 个可达落点。分叉层对进入分叉前的位置必须恰好 2 个可达落点。不得出现玩家看见两块板、却只有一块跳得到的假双选。

### GAME-GEN-005 可替换规则

层数据只存掩码，不把「不能跨列」写进层本身。

生成器接收当前移动规则。第一版只用 `Adjacent`。预留 `Cross`：左也可以落到右，右也可以落到左。

新角色或强化若开启跨列，从**下一关生成**开始改用新规则。本关已生成的数据不重算。

第一版不得为了预留跨列，提前摆出当前规则够不着的板。

## 5. 生成本关

### GAME-GEN-006 进关生成

只生成即将开始的这一关。倒计时 `GO!` 之前必须齐：

- 实际层数（默认 50，受层数强化后为 40～60）。
- 每一层掩码。
- 主路每一层的安全列。
- 每个分叉窗口的两条支路列序列和收束列。
- 果实所在层与种类。
- 起点列和终点列。

不得提前生成后续关卡。画面仍只实例化当前落地平台和下一块可见平台。

### GAME-GEN-007 生成顺序

1. 用当前移动规则生成一条覆盖全关的单路主路径，每一步都可达。
2. 起点优先中列。
3. 在第 11～45 层窗口内放入 1～3 个短分叉。
4. 每个分叉改写对应 3 层：分开、保持两路、第 3 层收束。
5. 写入果实槽位。果实只放在该层至少一条安全路上。
6. 校验：从起点沿任意分叉选择都能走到终点，且不违反现行移动规则。

## 6. 单路

### GAME-GEN-008 单路层

下列区段必须是单路，每层恰好一块可达板：

- 第 1～10 层。
- 两次分叉之间的间隔层。
- 第 46 层到本关最后一层。
- 不处于分叉第 1、2 层的所有其他层。

单路段不得再随机加第二块板。

### GAME-GEN-009 主路径约束

主路径必须满足《关卡结构与难度曲线》的操作平衡：不得长期只出现同一种正确手势；相同手势连续次数遵守该文档初始上限。

## 7. 短分叉

### GAME-GEN-010 次数与窗口

每一关生成 **1～3 次** 短分叉，且只出现在第 **11～45 层**。

分叉起点层 `S` 必须同时满足：

- `11 ≤ S ≤ 45`
- `S + 2` 不超过本关最后一层
- 第 46 层及之后不得处于分叉第 1、2 层

40 层关：窗口改为第 11 层到「最后一层再往前 5 层」，并保证 `S + 2` 仍在关内。60 层关：仍用第 11～45 层，不把分叉放到第 46 层之后。

### GAME-GEN-011 三层结构

每一次分叉固定占用 3 层：

| 相对层 | 作用 | 选择数 |
|---|---|---|
| `S` | 从单路劈成两条可达路 | 2 |
| `S+1` | 两条路继续，互不相交成死路 | 2 |
| `S+2` | 两条路收到同一列 | 1 |

「分叉持续两层、第三层必须收束」指 `S` 与 `S+1` 为双路，`S+2` 为单路收束。

### GAME-GEN-012 间隔

任意两次分叉占用的 3 层不得重叠。两次分叉之间至少隔 **1 层单路**。

因此两个起点至少相距 4 层。例如起点为 12，下一次最早为 16。

### GAME-GEN-013 支路生成

- 两条支路从 `S` 的两个不同可达列出发。
- `S` 和 `S+1` 上，两条支路所在列不得相同。
- 每一跳仍遵守当前移动规则。
- `S+2` 必须选一个两条支路都能落到的列。默认相邻规则下，左与右的公共落点是中；左与中可收到左或中；中与右可收到中或右。
- 收束后，主路径从该列继续单路直到下一分叉或终点。

### GAME-GEN-014 分叉中的操作

分叉第 1、2 层有两个正确落点，对应两个合法手势。选其中任一安全列均算正确，错误方向仍坠落。

收束层恢复为一个正确落点。

## 8. 层数变化

### GAME-GEN-015 40～60 层

实际层数不是 50 时：

- 第 1～10 层仍为单路热手；若总层数小于 20，热手改为前 20%。
- 分叉次数仍为 1～3，但必须能放下且不重叠。放不下 3 次时减到能放下的最大次数，至少 1 次。
- 最后 5 层保持单路。

## 9. 与其他系统

### GAME-GEN-016 果实

果实占用单路安全层，或分叉层上两条支路都经过的列。不得只放在其中一条支路上，避免逼玩家为吃果实选边。

牙齿等运行时插入物只能挂到「下一安全层」的安全列上，不得把单路改成双路，也不得拆掉收束。

### GAME-GEN-017 朝向与手势

朝向按《核心操作与跳跃判定》由目标列反推。双路层按玩家最终选择的那一个安全列计算朝向与评分。

## 10. 数据

每一关逻辑数据至少包含：

```text
stageSeed
layerCount
startColumn
endColumn
layers[i].mask          // (L, M, R)
layers[i].safeColumns   // 单路1个，分叉第1、2层2个，收束1个
forks[]                 // { startLayer, branchA[2], branchB[2], mergeColumn }
fruits[]                // { layer, column, type }
moveRule                // Adjacent（第一版）
```

## 11. UI 与表现

- 玩家至少能看清下一块安全平台。
- 分叉层两块板都必须能在输入截止前辨认。
- 不把整关 50 层模型一次放进场景。

## 12. 埋点

至少记录：

- 本关随机种子。
- 本关分叉次数与各次起点层。
- 玩家在每个分叉选择了哪条支路。
- 因方向错误死亡时的层号、当前列、当层掩码。
- 是否出现生成校验失败并重试。

## 13. 验收标准

### GAME-GEN-ACC-001 相邻不可跨列

- Given 当前规则为 Adjacent，玩家在左列，当层为 `(1,0,0)`
- When 系统生成下一层
- Then 下一层必须包含左或中，不得只生成 `(0,0,1)`

### GAME-GEN-ACC-002 热手单路

- Given 标准 50 层关
- When 生成完成
- Then 第 1～10 层每一层选择数均为 1

### GAME-GEN-ACC-003 分叉窗口

- Given 标准 50 层关
- When 生成完成
- Then 分叉次数为 1、2 或 3；每次起点在 11～45 层；第 46～50 层选择数均为 1

### GAME-GEN-ACC-004 三层收束

- Given 一次分叉起点为 S
- When 玩家走完 S、S+1、S+2
- Then S 与 S+1 各有 2 个可达落点，S+2 只有 1 个可达落点，且两条支路都能落到该列

### GAME-GEN-ACC-005 间隔

- Given 本关生成了至少两次分叉
- When 检查占用层
- Then 任意两次占用的三层不重叠，且中间至少有 1 层单路

### GAME-GEN-ACC-006 无假双选

- Given 任意一层存在两块板
- When 按玩家进入该层前所在列计算可达
- Then 两块板都必须可达；不得出现看得见却跳不到的板

### GAME-GEN-ACC-007 不分后续关

- Given 玩家即将进入第 3 关
- When 第 3 关倒计时开始
- Then 只存在第 3 关层数据，不存在第 4 关及之后的层数据

### GAME-GEN-ACC-008 跨列预留

- Given 第一版移动规则为 Adjacent
- When 检查层数据格式
- Then 层数据不含写死的“禁止跨列”字段，仅保存掩码；移动规则作为本关生成参数单独记录
