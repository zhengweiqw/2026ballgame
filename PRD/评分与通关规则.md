# 评分与通关规则需求文档

> 状态：草案  
> 目标版本：V1 微信小游戏  
> 负责人：待定  
> 最近更新：2026-09-01

## 1. 背景与目标

评分系统用于衡量玩家观察角色朝向、判断目标平台，并在最佳起跳时机完成正确手势的准确度。

评分系统需要满足：

- 正确操作至少获得基础分。
- 越接近最佳起跳时机的正确操作获得越高评分。
- 轻点、上划和下划都有公平的评分机会。
- 错误方向和输入超时不能获得分数。
- 玩家可以理解本次获得某个评价的原因。
- 评分可以支持关卡保底分、强化和后续高分竞争。

## 2. 范围

### 2.1 本期包含

- GOOD、GREAT、PERFECT三级评价。
- 三级评价基础分数。
- 判定计时起点和动态最佳起跳时刻。
- 轻点的判定完成时刻。
- 上划和下划的判定完成时刻。
- 三类操作的初始最佳时机判定窗口。
- 单关分数计算。
- 实际层数变化后的保底分计算。
- 分数强化的基础接口要求。
- 评分UI和反馈要求。

### 2.2 本期不包含

- 最终连击系统。
- 排行榜规则。
- 好友分数竞争。
- 无限模式分数倍率。
- 金币结算公式。
- 第20关奖励。
- 完整强化数值。

## 3. 核心原则

### GAME-SCORE-001 判断顺序

每次输入必须按以下顺序处理：

1. 判断玩家是否在有效时间内完成操作。
2. 判断轻点、上划或下划是否正确。
3. 操作正确时记录操作完成时刻。
4. 计算操作完成时刻与本次最佳起跳时刻的绝对误差。
5. 根据时间误差产生评价。
6. 根据评价增加分数。

时机再准确的错误操作也不能获得评分。

### GAME-SCORE-002 成功评价

第一版只设置：

- GOOD
- GREAT
- PERFECT

不增加 Normal、Bad、OK 等额外成功等级。

### GAME-SCORE-003 失败评价

以下情况记为 MISS：

- 操作方向错误。
- 未在输入截止时间内完成操作。
- 未落到有效平台。

MISS获得0分，并进入对应死亡流程。

## 4. 基础分数

### GAME-SCORE-004 评价分值

第一版暂定：

```text
GOOD：100分
GREAT：130分
PERFECT：170分
MISS：0分
```

### GAME-SCORE-005 分值关系

- GREAT比GOOD增加30%。
- PERFECT比GOOD增加70%。
- PERFECT比GREAT增加40分。

该分值用于第一版灰盒和平衡测试，不代表不可调整的最终上线值。

### GAME-SCORE-006 基础关卡分数范围

标准50层关卡中：

```text
全部GOOD：5000分
全部GREAT：6500分
全部PERFECT：8500分
```

上述数值不包含强化、连击、活动或其他倍率。

## 5. 判定时刻与最佳起跳时刻

### GAME-SCORE-007 判定开始时刻

同时满足以下条件时记录 `DecisionReadyTime`：

- 角色已落到当前平台。
- 角色已完成转身并锁定朝向。
- 下一安全平台已清晰显示。
- 系统已进入可输入状态。

系统不得在玩家尚未看清朝向或平台时开始有效输入窗口。

### GAME-SCORE-007A 最佳起跳时刻

每次跳跃必须根据当前平台位置、目标平台位置、平台下坠速度和角色跳跃参数，计算动态的 `IdealJumpTime`。

- `IdealJumpTime` 代表本次操作最适合生效的时刻。
- 平台速度变化时，`IdealJumpTime` 可以变化。
- 不得把450～600ms作为所有关卡固定不变的绝对区间。
- UI、角色蓄力动作或平台提示必须让玩家能够感知最佳时机正在接近。

### GAME-SCORE-008 轻点完成时刻

轻点需要在玩家松手后才能确认没有达到滑动阈值，因此轻点以松手时刻作为 `CommandTime`：

```text
轻点时间误差 = |轻点确认松手时间 - IdealJumpTime|
```

### GAME-SCORE-009 滑动完成时刻

上划或下划以手指纵向移动首次达到滑动阈值的时刻作为 `CommandTime`：

```text
滑动时间误差 = |首次达到滑动阈值的时间 - IdealJumpTime|
```

达到阈值后立即锁定，不使用最终松手时间评分。

### GAME-SCORE-010 暂停时间

以下时间不得推进有效输入窗口或最佳起跳时刻：

- 游戏暂停
- 切入后台
- 平台广告播放
- 系统授权弹窗
- 支付弹窗

恢复游戏后必须先进入短暂准备状态，再重新开始判定。

## 6. 通用最佳时机评分窗口

### GAME-SCORE-011 初始判定窗口

轻点、上划和下划第一版默认使用同一时间误差窗口：

```text
PERFECT：时间误差 ≤ 75ms
GREAT：时间误差为76～225ms
GOOD：时间误差 > 225ms，但操作仍在有效输入时间内
MISS：超过输入截止时间
```

该规则奖励“卡准时机”，不是单纯奖励最快输入。明显提前完成正确操作也只能获得GOOD或GREAT。

### GAME-SCORE-012 450～600ms示例

假设：

```text
DecisionReadyTime = 10.000秒
IdealJumpTime = 10.525秒
```

那么相对于判定开始时刻：

```text
PERFECT区间 = 450～600ms
GREAT提前区间 = 300～449ms
GREAT延后区间 = 601～750ms
GOOD区间 = 0～299ms，或751ms至输入截止时间
```

450～600ms只是最佳起跳时刻为525ms时的示例。其他跳跃的实际区间由 `IdealJumpTime` 动态平移。

## 7. 轻点、上划与下划示例

### GAME-SCORE-013 轻点示例

假设本次：

```text
DecisionReadyTime = 10.000秒
IdealJumpTime = 10.525秒
```

不同松手时刻对应：

```text
10.500秒松手：误差25ms，PERFECT，170分
10.380秒松手：误差145ms，GREAT，130分
10.230秒松手：误差295ms，GOOD，100分
```

### GAME-SCORE-014 上划示例

假设正上方为安全平台，且：

```text
DecisionReadyTime = 20.000秒
IdealJumpTime = 20.525秒
玩家向上移动达到阈值 = 20.590秒
玩家松手 = 20.700秒
```

系统以达到阈值的20.590秒作为操作完成时间：

```text
时间误差 = |20.590 - 20.525| = 65ms
评价 = PERFECT
分数 = 170
```

### GAME-SCORE-015 下划示例

假设角色面朝右，安全平台在左侧，正确操作为下划：

```text
DecisionReadyTime = 20.000秒
IdealJumpTime = 20.525秒
玩家向下移动达到阈值 = 20.700秒
```

时间误差为175ms，因此：

```text
评价 = GREAT
分数 = 130
```

如果达到阈值时间为20.800秒，且未超过输入截止时间：

```text
时间误差 = 275ms
评价 = GOOD
分数 = 100
```

## 8. 正确性优先

### GAME-SCORE-016 错误操作示例

假设：

- 角色面朝左。
- 安全平台在正上方。
- 正确操作为上划。
- 玩家在100ms内完成轻点。

虽然操作时刻达到PERFECT窗口，但轻点会使角色向左跳，因此：

```text
评价 = MISS
分数 = 0
结果 = 坠落死亡
```

系统不得因为操作速度快而修正错误方向。

## 9. 单关分数

### GAME-SCORE-017 原始评价分

单关原始评价分计算：

```text
原始评价分 =
GOOD数量 × 100
+ GREAT数量 × 130
+ PERFECT数量 × 170
```

### GAME-SCORE-018 强化后分数

如果玩家拥有得分强化：

```text
强化后评价分 = 原始评价分 × 得分倍率
```

例如得分增加15%：

```text
得分倍率 = 1.15
```

小数取整方式尚未确认。

### GAME-SCORE-019 展示分数

- 分数必须使用整数显示。
- GOOD默认显示小型加分数字。
- GREAT显示评价文字、加分数字和增强音效。
- PERFECT显示评价文字、加分数字、特殊音效和明显落地反馈。
- 评分反馈不得长时间遮挡下一安全平台。

## 10. 保底分

### GAME-SCORE-020 标准关卡建议值

标准50层关卡的初始保底分建议为：

```text
5500分
```

达到5500分的部分示例：

- 17次GREAT，其余GOOD。
- 8次PERFECT，其余GOOD。
- 5次GREAT、5次PERFECT，其余GOOD。
- 10次GREAT、3次PERFECT，其余GOOD。

### GAME-SCORE-021 动态保底分

当强化改变关卡层数时，保底分初始建议按以下公式计算：

```text
保底分 = 实际层数 × 110
```

对应：

```text
40层：4400分
50层：5500分
60层：6600分
```

### GAME-SCORE-022 保底分状态

UI必须持续显示：

- 当前分数
- 当前目标分
- 是否已达到目标
- 还差多少分

玩家不得在关卡结束时才第一次得知存在保底分。

## 11. 分数检查频率

### GAME-SCORE-023 候选方案A：每关检查

每关结束时检查本关分数：

- 达到保底分：进入下一关。
- 未达到保底分：进入分数失败死亡流程。

风险：

- 与跳错即死叠加后淘汰率可能过高。
- 单关偶然发挥不佳无法追回。
- 连续20关的累计通关率可能过低。

### GAME-SCORE-024 候选方案B：每5关累计检查

每关显示目标和得分，但在第5、10、15、20关结束时检查本章节累计分数：

- 达到章节目标：通过章节。
- 未达到章节目标：进入分数失败流程。

优点：

- 单关失误可以通过后续表现追回。
- 与强化选择节点一致。
- 减少重复淘汰造成的挫败。

当前推荐方案B，但尚未由产品正式确认。

## 12. 分数失败

### GAME-SCORE-025 分数失败表现

分数失败必须与跳错死亡使用不同表现，避免玩家无法理解原因。

可选表现：

- 平台能量不足并崩塌。
- 追赶进度条耗尽。
- 角色未达到本章节要求，被下坠环境追上。

最终表现待确认。

### GAME-SCORE-026 分数失败提示

失败界面至少显示：

- 当前分数
- 目标分数
- 差值
- GOOD、GREAT、PERFECT数量
- 改善建议
- 是否可广告复活或补救

## 13. 连击与额外倍率

第一版是否增加连击尚未确认。

如后续加入，必须明确：

- 哪些评价增加连击。
- GOOD是否中断连击。
- 连击倍率上限。
- 连击是否影响保底分。
- 连击是否只影响排行榜和金币奖励。

在规则确认前，基础保底分不得依赖连击倍率。

## 14. 难度和平衡原则

### GAME-SCORE-027 操作公平

- 轻点和滑动的动作成本不同，但第一版先使用相同的最佳时机误差窗口。
- 玩家可以更早开始滑动，使滑动达到阈值的时刻落入最佳区间。
- 三种操作获得PERFECT的实际概率应该大致接近。
- 若真机数据差异显著，应优先调整滑动距离和提示时机，再考虑为不同操作增加小幅时间补偿。

### GAME-SCORE-028 窗口测试

真机测试至少统计：

- 轻点平均操作完成时间和平均时间误差。
- 上划平均操作完成时间和平均时间误差。
- 下划平均操作完成时间和平均时间误差。
- 三种操作的GOOD比例。
- 三种操作的GREAT比例。
- 三种操作的PERFECT比例。
- 各操作误识别率。
- 各关输入超时率。

### GAME-SCORE-029 判定窗口调整

如果某种操作的PERFECT比例显著低于其他操作，应优先检查：

1. 手势识别阈值。
2. 角色朝向可读性。
3. 平台出现时机。
4. 输入延迟。
5. 该操作判定窗口。

不能只通过提高分数掩盖输入体验问题。

### GAME-SCORE-030 难度叠加

平台下坠速度已经会随关卡提高。

判定窗口是否随关卡缩短尚未确认。第一版建议先保持评分窗口不变，通过平台节奏增加压力，避免同时缩短窗口造成双重加难。

## 15. UI、动画和音效

### 15.1 GOOD

- 小型加分数字。
- 普通落地音效。
- 不使用大面积特效。

### 15.2 GREAT

- 显示 GREAT。
- 更明显的加分数字。
- 强化落地音效。
- 轻微闪光或缩放。

### 15.3 PERFECT

- 显示 PERFECT。
- 最明显的加分数字。
- 独特落地音效。
- 明显但短暂的落地特效。
- 可以使用轻微震动。

### 15.4 显示限制

- 所有评价文字必须快速出现并消失。
- 评价不得挡住角色朝向。
- 评价不得挡住下一安全平台。
- 连续快速跳跃时，旧评价必须及时清理或合并。

## 16. 埋点

至少记录：

- 每次操作类型。
- 操作是否正确。
- 操作完成时间。
- 本次最佳起跳时刻。
- 与最佳起跳时刻的时间误差。
- 获得评价。
- 本关GOOD数量。
- 本关GREAT数量。
- 本关PERFECT数量。
- 本关原始评价分。
- 强化后评价分。
- 保底目标分。
- 是否通过分数检查。
- 分数失败时差值。

## 17. 验收标准

### GAME-SCORE-ACC-001 GOOD基础分

- Given 玩家正确完成操作且与最佳起跳时刻的误差落在GOOD区间
- When 本次评分结算
- Then 本次增加100分

### GAME-SCORE-ACC-002 GREAT基础分

- Given 玩家正确完成操作且与最佳起跳时刻的误差落在GREAT区间
- When 本次评分结算
- Then 本次增加130分

### GAME-SCORE-ACC-003 PERFECT基础分

- Given 玩家正确完成操作且与最佳起跳时刻的误差落在PERFECT区间
- When 本次评分结算
- Then 本次增加170分

### GAME-SCORE-ACC-004 错误操作

- Given 玩家在PERFECT时间内完成错误操作
- When 系统判断操作方向
- Then 本次得0分并进入死亡流程，不得产生PERFECT

### GAME-SCORE-ACC-005 轻点最佳时机

- Given 玩家在10.000秒进入可输入状态，最佳起跳时刻为10.525秒
- When 玩家在10.500秒完成轻点松手
- Then 时间误差为25ms，评价为PERFECT

### GAME-SCORE-ACC-006 滑动最佳时机

- Given 玩家在20.000秒进入可输入状态，最佳起跳时刻为20.525秒
- When 玩家在20.590秒首次达到滑动阈值并在20.700秒松手
- Then 时间误差为65ms，评价为PERFECT，松手时间不影响结果

### GAME-SCORE-ACC-007 动态保底分

- Given 本关实际层数为40层
- When 系统计算建议保底分
- Then 目标分为4400分

### GAME-SCORE-ACC-008 暂停

- Given 玩家处于评分计时期间
- When 游戏暂停2秒后恢复
- Then 最佳起跳时刻和输入截止时间同步顺延2秒，评分不受暂停影响

## 18. 待确认事项

1. 保底分是否最终采用每层110分。
2. 分数检查采用每关检查还是每5关累计检查。
3. 分数不足是否立即死亡。
4. 是否提供一次警告或补分机会。
5. 分数失败的具体世界观表现。
6. PERFECT ±75ms和GREAT ±225ms是否作为最终窗口。
7. 动态最佳起跳时刻的具体计算公式。
8. 各关输入截止时间。
9. 是否为不同操作增加时间补偿。
10. 得分强化是否影响保底分。
11. 得分强化的小数取整规则。
12. 是否加入连击。
13. 连击是否影响保底分。
14. GOOD是否只显示加分数字。
